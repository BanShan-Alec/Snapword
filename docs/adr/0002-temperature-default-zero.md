# ADR-0002：翻译请求默认 temperature=0

- 状态：已接受
- 日期：2026-11-04
- 相关：PRD FR-17、`docs/prompt-contract.md` §2/§4、B-07 评测集

## 背景

PRD FR-17 把 temperature 列为配置项，默认 0.3；B-04 当前固定 0.3。本轮以沉浸式翻译的默认值（0）为参考，讨论“确定性”与“单词多义项覆盖”的关系。

需要区分两件事：

- **temperature 控制采样随机性**，影响 JSON 合法性、义项顺序、释义措辞、例句多样性、重试能否逃逸、评测可复现性。
- **义项数量不由 temperature 控制**。模型在 temperature=0 下仍会输出它认为最可能的多个义项；覆盖多少义项由提示词与 schema 决定。

## 决策

1. 单词模式与句子模式的默认 temperature 都改为 **0**，用户可在设置中修改；测试连接恒为 0。
2. temperature=0 不承担“增加义项数量”的职责。义项覆盖由 `word-v1` 的提示词与 schema 控制。目标与约束：
   - 尽量列出常见义项，按常见度与语境相关度排序；
   - 多义词至少 2 条，只有一个常见义项时只给 1 条；
   - 禁止为了凑数编造生僻、古旧或高度专业化的义项；
   - 每条义项有对应例句；
   - 有 context 时，`context_sense` 对应义项排第一。
     具体条数上限、例句语言、`example` 是否由 `string | null` 改为必填，在 B-04 修订时确认。
3. 评测集 B-07 以 temperature=0 跑基线；若义项覆盖率不达标，先改提示词与 schema，再考虑单词模式 0.1–0.2 的调参，不直接改默认值。
4. 同步修改 PRD FR-17 的默认值 0.3 → 0，以及 B-04 §2 参数表。

## 理由

- 翻译和 JSON 输出偏好确定性：字段结构、义项顺序、措辞更稳定，JSON 解析成功率更高。
- temperature=0 不会让模型只输出一个义项；0.3 带来的“多样性”主要是措辞与顺序波动，不是稳定覆盖更多常见义。
- 评测可复现：同一评测集在 0 下可重复比较提示词版本；0.3 需要多次运行取平均。
- 沉浸式翻译的默认值也是 0，说明翻译场景下低温度是可行选择。

## 后果

- PRD FR-17 默认值需从 0.3 改为 0；设置页仍允许用户修改。
- 重试策略保持不变：JSON 失败时追加约束（改变 prompt），避免 temperature=0 下重复同一坏输出。
- 单词模式的义项条数上限、例句语言、`example` 是否必填仍需在 B-04 修订时确定；本 ADR 只确认“义项覆盖不靠温度”。
- 评测结果应记录 temperature 与 promptVersion，避免不同温度下的结果混在一起比较。

## 备选方案

- 单词 0.3 / 句子 0：保留单词措辞多样性，但 JSON 稳定性和评测复现性下降；暂不采用。
- 保持 0.3：与 PRD 现状一致，但不符合“确定性优先”的目标。
- 单词 0.1–0.2 / 句子 0：作为评测不达标时的调参手段，不作为默认值。
