# ADR-0006：翻译卡片重构为固定视口与原生无边框窗口

- 状态：已接受
- 日期：2026-11-23
- 相关：PRD RC-01 / RC-02 / RC-03 / RC-13 / RC-18、`packages/shared/src/constants/window-geometry.ts`、`packages/main/src/modules/window/card-window.module.ts`、`packages/renderer/src/features/card/index.tsx`

## 背景

翻译卡片此前采用 **“透明分层窗口（`transparent: true`）+ 动态内容高度伸缩（`ResizeObserver -> IPC -> win.setSize`）+ 16px CSS 微阴影呼吸留白”** 架构。

在业务主链路贯通后，通过高频流式翻译与实机拖拽回归，暴露了以下无法调和的交互与工程缺陷：
1. **幽灵外框破坏屏幕吸附与拖拽手感**：为容纳 CSS `box-shadow` 发散，物理窗口四周垫入了 16px 透明留白。Windows DWM 的 Hit-Testing 与系统的边缘吸附回弹算法（`calculateCardRebound`）以物理外框为准，导致卡片在拖近屏幕底部或任务栏时发生“半空过早回弹”，无法自然贴底。
2. **状态重置（重试 / 清空）的时序脱节**：用户点击“重试”或网络报错时，内容瞬间收敛为骨架屏（Skeleton），但窗口几何高度若带有防抖/阶梯滞后，会导致卡片下方留出大面积悬空空白，界面产生突兀闪跳。
3. **流式高频调用的性能隐患**：随着模型流式生成长文本，内容高度频繁变动，高频触发跨进程 IPC 与 Win32 `SetWindowPos` 系统重排。

## 决策

经过对工业界成熟应用（1Password Quick Access、Raycast、pot-desktop、DeepL）的方案论证，决定全面转向 **流派 2（固定视口 + 超长主窗口承接）**，具体架构决策如下：

1. **确立单一固定物理视口（Fixed Viewport）**：
   - 废除任何动态 `win.setSize` 机制，翻译卡片在唤起时不分单词或长句模式，均采用统一基准尺寸：**`400px 宽 × 280px 高` (DIPs)**。
   - 在低分辨率或高缩放比小屏幕设备上，叠加屏幕工作区保护上限夹限：`height = Math.min(280, Math.floor(workArea.height * 0.45))`。
2. **重构为原生无边框窗口（Native Frameless Window）**：
   - 彻底关闭 `transparent: false`，开启 `hasShadow: true` 与 `frame: false`。
   - 删除外层呼吸留白（`CARD_WINDOW_SHADOW_PADDING` 归零），物理窗口边界与肉眼可见的卡片边界 100% 契合（纯净 400×280）。
   - 阴影交由操作系统 DWM 投射原生阴影；Windows 11 下自动获得系统原生 8px 标准圆角，与主窗口、更新窗口达成 100% 视觉同源。
3. **长文视口内平滑滚动与主窗口协同承接**：
   - 280px 高度可完整容纳所有单词释义与 1~2 句常规译文；
   - 当遇到超长段落时，内容在卡片内部通过鼠标滚轮平滑滚动阅读，底部渲染微弱的渐变淡出遮罩（Fade Mask）；
   - 底部操作栏强化「在主窗口展开（或双击卡片）」动作，引导深度长文阅读平滑流转至主窗口。
4. **废除卡片 Resize IPC 通道**：
   - 删除 `card:resize` IPC 通道及其在主进程、Preload、渲染进程的监听代码，彻底消除跨进程尺寸调度。

## 理由

- **根除拖拽吸附所有 Bug**：物理窗口尺寸严格等于卡片视觉尺寸，拖拽到任务栏、屏幕上下左右边缘的回弹算法毫厘不差，松手手感达到纯原生级别。
- **系统级调用永久归零**：流式吐字期间，操作系统窗口尺寸绝对恒定，彻底终结了 Win32 `SetWindowPos` 调度开销、IPC 拥塞与任何潜在的底边频闪风险。
- **状态切换干脆稳定**：重试、换词、报错时，卡片几何外框岿然不动，只有内部文字骨架无缝切换，完全消除“骨架屏悬空脱节”问题。
- **视觉层级高度统一**：所有窗口均使用操作系统 DWM 阴影与原生边框，不再存在“CSS Web 阴影”与“原生系统阴影”并存的质感割裂。
- **显存与冷启动优化**：普通不透明窗口无需维护 DirectComposition 分层透明表面，首帧渲染更快，显存占用降低。

## 后果

- **正向**：卡片交互坚如磐石，代码复杂度大幅降低（删除了动态 Resize 状态机与外框垫片），多屏高缩放兼容性极高。
- **代价与取舍**：3 句以上或数百字长文在卡片内无法一眼看全，需要滚轮滚动或点击跳转至主窗口。符合“划词卡片负责轻量即时查阅，主窗口负责深度沉浸阅读”的产品分工定位。

## 备选方案

- **备选 1：紧凑自绘透明层 + 逐像素实时 Resize**：需持续维护透明通道与呼吸外边距，无法解决极端高频打字时的跨进程微延迟。
- **备选 2：阶梯步长自适应（Bucketed Resize 垫透明空白）**：实机测试证实底部垫入的幽灵空白会严重破坏拖拽松手吸附与重试状态切换，已被否决。
