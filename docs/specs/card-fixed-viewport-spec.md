## Problem Statement / 问题陈述

在现有的翻译卡片实现中，由于采用了「透明分层窗口 + 内容高度动态自动伸缩 + 16px CSS 阴影呼吸外边距」方案，在实际阅读和流式翻译中暴露出了一系列无法回避的交互与工程缺陷：

1. **拖拽贴边失真与悬空回弹**：为容纳向外扩散的 CSS `box-shadow`，物理窗口四周垫入了 16px 透明留白（窗口总宽达 452px）。操作系统 DWM 的碰撞检测与边缘吸附回弹算法以物理外框为准，导致用户试图将卡片拖向任务栏或屏幕底边时，系统误判边界发生“过早回弹”，卡片悬在半空无法贴底；松手后强加的 16px 视口吸附更是产生突兀的弹跳感，破坏了桌面窗口“所见即所得”的自然手感。
2. **状态重置（重试/清空）导致骨架屏脱节悬空**：当用户点击“重试”或遇到网络报错时，界面瞬间切换为紧凑的骨架屏（Skeleton），但窗口物理高度因防抖滞后无法瞬间收缩，导致卡片下半部分露出大面积尴尬的悬空空白，新翻译流式返回时又发生跳突。
3. **流式打字的高频系统重排与时序撕裂隐患**：随着模型流式生成长文本，内容高度频繁变动，每一两行就触发一次跨进程 IPC 与 Win32 `SetWindowPos` 重排，带来无谓的系统负载与微掉帧；若使用不透明窗口变高，又会因 Electron 跨进程渲染时序差在底边暴露背景色频闪。
4. **设计风格与桌面原生环境割裂**：自绘的 16px 移动端式大圆角和扩散型 CSS 阴影，与主窗口、更新窗口的原生系统 DWM 阴影及 Windows 11 系统级 8px 标准圆角风格存在质感割裂。

## Solution / 解决方案

全面废弃高度动态伸缩与透明外框垫底设计，将翻译卡片重构为 **「固定视口（Fixed Viewport）+ 原生无边框（Native Frameless）」** 架构：

1. **单一固定物理视口**：
   - 确立统一基准尺寸：**`400px 宽 × 280px 高` (DIPs)**，不随流式吐字、单词/句子模式或重试状态发生任何物理尺寸改变；
   - 在低分辨率或高缩放比小屏幕设备上，叠加屏幕工作区高度 45% 的上限安全夹限，防止超大遮挡。
2. **全面回归原生无边框窗口**：
   - 窗口底层切换为 `transparent: false`、`frame: false`、`hasShadow: true`；
   - 彻底删除外层呼吸留白垫底，物理窗口尺寸严格等于卡片视觉尺寸（纯净 400×280）；
   - 阴影交由操作系统 DWM 原生渲染，Windows 11 下自然获得系统原生 8px 标准圆角与原生微描边，与主窗口和系统环境达成 100% 视觉同源。
3. **长文视口内平滑滚动 + 底部弱淡出 + 强化主窗口流转**：
   - 280px 高度自洽容纳常见单词查词与 1~2 句常规翻译；
   - 遇到长文本时，内容在卡片内部通过鼠标滚轮平滑滚动；
   - 视口底部渲染轻量渐变淡出遮罩（Fade Mask）直观提示下方有更多内容；
   - 底部操作栏显著强化「在主窗口展开（或双击卡片头部/空白处快速在主窗口打开）」动作，引导长文阅读无缝流转至主窗口。
4. **彻底废除松手强制吸附回弹算法**：
   - 废除松手强制弹开 16px 的回弹重设逻辑；
   - 用户将卡片拖到哪里就停在哪里，仅在初始化弹出时做防越界计算，拖拽手感完全回归桌面原生。
5. **彻底删除 `card:resize` IPC 管道**：
   - 废除渲染层向主进程发送高度变化的通道与相关状态机，流式生成期间系统级调用永久归零。

## User Stories / 用户故事

1. 作为技术读者，我希望划词触发卡片时，卡片呈现固定、稳健的尺寸，以便我的阅读视线不会被上下伸缩抖动的卡片所干扰。
2. 作为技术读者，当我查询简短单词时，我希望卡片在固定视口内紧凑清晰地呈现音标、发音与常见释义，以便我快速获取词义。
3. 作为技术读者，当我翻译常见的一两句英文时，我希望卡片固定视口能恰好容纳完整译文，以便我无需任何多余操作直接扫读。
4. 作为技术读者，当我遇到超长段落翻译时，我希望可以在卡片内部用鼠标滚轮平滑滚动查看全部内容，以便我无需频繁切换窗口也能读完全文。
5. 作为技术读者，当卡片内容超出视口时，我希望卡片底部有微弱的淡出渐变提示，以便我直观感知到下方仍有未展示完的内容。
6. 作为技术读者，当我在卡片中浏览长文本时，我希望点击底栏的「在主窗口展开」按钮，以便将完整翻译无缝流转到大窗口进行沉浸阅读。
7. 作为技术读者，当我拖动翻译卡片时，我希望把卡片拖到哪里它就停在哪里，以便我可以把它精准贴靠在屏幕边缘或任务栏上方。
8. 作为技术读者，当我松开拖拽卡片的鼠标时，我希望卡片不要产生任何诡异的弹跳或自动弹开，以便获得符合操作系统直觉的纯净手感。
9. 作为技术读者，当我点击卡片的「重试」按钮时，我希望界面瞬间重新加载且卡片外框纹丝不动，以便不会出现骨架屏与卡片外框脱节的悬空空洞。
10. 作为技术读者，当网络报错或查词未命中时，我希望卡片外框保持稳定并就地展示提示文案，以便界面保持平稳。
11. 作为 Windows 11 用户，我希望翻译卡片的阴影和微圆角与系统原生窗口（如主窗口）保持一致，以便软件视觉风格高度统一、专业。
12. 作为高分屏笔记本用户，当我在 150% 缩放或 768p 屏幕上使用 Snapword 时，我希望卡片高度不会侵占超过工作区的一半，以便保留充足的阅读上下文视野。
13. 作为技术读者，在流式翻译逐字生成过程中，我希望卡片底部绝对不出现任何黑条、白闪或闪烁，以便保持专注的阅读心流。
14. 作为技术读者，当卡片悬浮在桌面上时，我希望卡片周围的桌面图标与网页链接可以自由点击，以便不会受到隐形透明留白的意外拦截。
15. 作为技术读者，当我调整完卡片位置后，我希望在本次应用运行期间卡片记住该位置，以便后续查词时都在我习惯的舒适区域呈现。
16. 作为技术读者，当我在卡片内阅读时，我希望可以使用键盘方向键与滚轮快捷翻看内容，以便提高操作效率。
17. 作为低配设备用户，我希望卡片窗口占用极少的 GPU 显存且没有频繁的系统调用，以便整机保持轻快流畅。
18. 作为技术读者，当我双击卡片头部非控件区域时，我希望卡片能够快捷触发在主窗口展开，以便更高效地完成长文交互切换。

## Implementation Decisions / 实施决策

### 1. 几何尺寸契约归一化（Geometry Contract）

- 确立卡片基准尺寸为宽度 400 DIPs、高度 280 DIPs。
- 彻底废除 `CARD_WINDOW_SHADOW_PADDING`（阴影呼吸留白）常量，物理宿主窗口宽度严格定为 400 DIPs。
- 屏幕安全高度计算规则：
  - 在计算卡片边界时，目标高度按 `Math.min(280, Math.floor(workArea.height * 0.45))` 计算，确保在 768p 或 1080p@150%（可用高度仅 680 DIPs）设备上高度不超过屏幕可用高度的 45%。
  - 目标宽度按 `Math.min(400, Math.max(100, workArea.width - 32))` 夹限。

### 2. 主进程窗口架构重构（BrowserWindow Architecture）

- 卡片窗口配置切换为原生无边框模型：
  - `frame: false`
  - `transparent: false`
  - `hasShadow: true`（依托操作系统 DWM 投射原生阴影，Win11 自动获得原生 8px 系统圆角）
  - `backgroundColor` 继承并同步自全局主题色板（`getWindowBackgroundColor()`），杜绝初始化阶段的闪烁。
  - `resizable: false`，`alwaysOnTop: true`，`skipTaskbar: true`。

### 3. 拖拽吸附算法废除与自由停靠（Drag Decoupling）

- 彻底删除松手强制吸附回弹算法及其在窗口 `moved` 事件中的调用。
- 窗口 `moved` 事件仅保留持久化记录当前坐标：`this.lastDraggedPosition = { x, y }`。
- 初始弹出避让算法（`calculateCardBounds`）仅在首次计算出现位置时保证 400×280 窗口完整落入工作区内（避免选区遮挡与越界）；用户一旦手动拖动，窗口完全听从用户鼠标落点。

### 4. 通信管道精简与流式零系统开销（IPC Streamlining）

- 彻底废除 `card:resize` IPC 通道及其在 `@app/shared`、`@app/preload`、`@app/main` 的声明与监听。
- 渲染层删除驱动窗口伸缩的 `ResizeObserver`，流式生成期间不向主进程发送任何尺寸变更信号。

### 5. 渲染层布局与长文滚动承接（Renderer Layout & Scrolling）

- 渲染层最外层容器收缩为 `w-[400px] h-[280px]`，删除外层 `p-4` 垫底和 CSS `.floating-card-shadow`。
- 内容展示区设置固定高度与 `overflow-y: auto` 滚动容器，样式层集成 `usb-scroll-fade` 底部渐变淡出遮罩。
- 底部操作栏针对长文本状态强化「在主窗口展开」按钮的可见度，并支持双击头部快速调用 `openInHome`。

## Testing Decisions / 测试决策

遵循最高测试接缝（Highest Possible Seam）原则，专注于外部可见行为与契约校验，不测试内部实现细节：

### 1. 窗口几何与屏幕夹限计算接缝（Geometry Contract Seam）

- **测试模块**：卡片几何纯函数模块
- **测试重点**：
  - 验证在标准 1080p 屏幕下，计算出的卡片尺寸恒为 400×280 DIPs；
  - 验证在低分屏（如工作区高度 720 DIPs）下，卡片高度被正确夹限为 `Math.floor(720 * 0.45) = 324` $\rightarrow$ 维持 280；
  - 验证在极端小屏（工作区高度 500 DIPs）下，卡片高度被正确夹限为 `225 DIPs`；
  - 验证手动拖拽记录的坐标被 1:1 沿用，未被多余的吸附算法修改；
  - 验证选区中心避让规则在固定尺寸下依然生效。

### 2. 渲染层固定视口与交互接缝（UI & Component Seam）

- **测试模块**：卡片 Feature 根组件与子组件
- **测试重点**：
  - 验证根容器固定为 400px 宽与 280px 高，未携带额外的外层呼吸内边距；
  - 验证短单词模式下布局正常呈现，无突兀空白；
  - 验证长句/流式翻译模式下，超出视口高度的内容可滚动，且淡出渐变遮罩正确挂载；
  - 验证点击「在主窗口展开」按钮正确触发 IPC 调用。

### 3. 主进程窗口装配接缝（Window Module Seam）

- **测试模块**：`CardWindowModule`
- **测试重点**：
  - 验证创建 `BrowserWindow` 时的参数为 `transparent: false`、`hasShadow: true`、`frame: false`；
  - 验证窗口尺寸严格为 400×280；
  - 验证不再注册 `card:resize` 监听，不存在跨进程调整尺寸的异步调度。

## Out of Scope / 范围外事项

1. **用户自由拖拉卡片边角手动缩放（Custom Manual Resizing）**：本期卡片为固定 400×280 视口，不提供右下角自由缩放手柄，避免引入双重尺寸管理复杂度。
2. **卡片内部长文分段分页卡片（Pagination inside Card）**：长文只通过平滑滚动和主窗口承接，不在卡片内设计“上一页/下一页”分页翻动。
3. **主窗口界面的结构调整**：主窗口接收 `openInHome` 后的展示沿用现有成熟流程，不属于本次卡片视口重构范围。
