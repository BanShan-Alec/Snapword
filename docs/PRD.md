## 二、背景与目标

### 2.1 背景

阅读英文资料时，理解一个词或一句话的现行做法是：选中 → 复制 → 切到浏览器/翻译网站 → 粘贴 → 读 → 切回原窗口 → 找回阅读位置。一次操作至少 6 个动作、2 次窗口切换，**打断了阅读的连续状态**，导致读者倾向于"跳过不懂的部分"，而不是"搞懂它"。

浏览器扩展可以解决网页内的划词问题，但无法覆盖桌面端阅读场景（PDF 阅读器、桌面客户端、独立窗口里的文档）。桌面工具的价值在于**跨应用**。

本项目为个人自用工具，同时开源发布供他人使用。**无服务器、无账号、无云服务**，所有翻译请求由用户自己的 API Key 直连用户自己配置的接口。

### 2.2 要解决的问题（按优先级）

| 编号 | 问题 | 现状痛点 |
|---|---|---|
| P-1 | 查词/翻译打断阅读心流 | 6 个动作、2 次窗口切换、需要重新定位阅读位置 |
| P-2 | 查到的译文不知道是不是"这个词在这个句子里的意思" | 通用翻译工具只给孤立译文，多义词常给出错误义项 |
| P-3 | 技术文档里的代码、变量名、命令行被翻译成中文，反而更难读 | 通用翻译工具无代码保护 |
| P-4 | 查过的词记不住、找不到 | 无统一的生词沉淀，散落在浏览器历史与笔记里 |
| P-5 | 现有工具要么收费、要么要求注册账号、要么把选中内容上传到自己的服务器 | 隐私不可控 |

### 2.3 产品目标

| 目标 | 衡量指标 | 目标值 | 口径 |
|---|---|---|---|
| G-1 缩短操作链路 | 从"选中"到"看到译文"的动作数 | ≤ 2 个动作（选中 + 点击气泡/热键） | 主流程动作计数，不含阅读本身 |
| G-2 降低等待感 | 气泡出现延迟 | P95 ≤ 120 ms | 鼠标抬起 → 气泡可见，本机渲染耗时 |
| G-3 降低等待感 | 译文首字可见延迟 | P95 ≤ 1.5 s | 点击气泡 → 首字渲染；**受外部接口与模型影响，非本产品完全可控**，仅作观测指标 |
| G-4 提升译文可用性 | 单词翻译的"语境义准确率" | ≥ 85% | 自建 50 词评测集（含多义词），人工判定首条义项是否与该句语境一致 |
| G-5 控制资源占用 | 常驻内存（含 Electron 主/渲染/宿主进程） | ≤ 250 MB | 空闲 10 分钟后任务管理器观测 |
| G-6 降低上手门槛 | 首次配置成功率 | ≥ 80% | 从首次启动到连通性测试通过的比例（本地日志统计，不上报） |

> G-4 与 G-6 为**设计目标值（估算）**，非实测数据；上线后按本地日志修正。

### 2.4 非目标

本产品**不追求**：成为通用翻译软件、替代词典 App、支持多语种、做语言学习平台。任何与"让英文阅读不被打断"无直接关系的需求，默认进入 v2 候选池而非本期范围。

## 三、名词与术语定义

| 术语 | 定义 |
|---|---|
| UIA | Windows UI Automation，微软的无障碍与自动化框架，可读取其他应用的 UI 元素与文本内容 |
| TextPattern | UIA 中的文本模式接口，用于读取文本内容、选区、并按单位扩展范围 |
| 气泡 | 选中文本后浮现在选区附近的小型按钮，仅承担"是否翻译"的确认作用 |
| 侧边栏 | 覆盖在其他窗口之上的悬浮结果面板，展示译文与相关操作 |
| 夺键焦 | 窗口获得键盘输入焦点，导致用户当前正在输入的窗口失去焦点 |
| 单词模式 | 选中内容被判定为单个英文词时的处理模式，返回词典化结构 |
| 句子模式 | 选中内容被判定为短语及以上时的处理模式，返回译文 |
| 占位符保护 | 送模型前把代码片段替换为不可翻译的占位标记，返回后还原的机制 |
| 术语表 | 用户维护的「词条 → 处理方式」配置，用于固定专业术语的译法或禁止翻译 |
| 会话历史 | 应用运行期间产生的翻译记录，仅存内存，退出即清空 |
| 生词本 | 用户主动收藏的条目，持久化到本地数据库 |
| 白名单进程 | 允许触发取词的应用进程列表，默认为 Chrome / Edge |
| 宿主进程 | 独立于 Electron 的 Windows 原生进程，负责全局钩子与 UIA 调用 |

## 五、方案对比与选型说明

### 5.1 取词方案

| 方案 | 实现成本 | 兼容面 | 副作用 | 稳定性 | 结论 |
|---|---|---|---|---|---|
| A. 纯 UIA（TextPattern.GetSelection） | 中（需原生进程） | 窄：依赖应用实现 UIA provider | 无（不碰剪贴板、不模拟按键） | 高（无时序竞争） | **采纳** |
| B. 模拟 Ctrl+C + 读剪贴板 | 低 | 广 | 高：剪贴板污染、与剪贴板管理器冲突、安全软件拦截、密码框风险 | 低（依赖时序与焦点） | 不采纳 |
| C. UIA 优先 + B 兜底 | 高（两套路径） | 最广 | 同 B | 中 | 不采纳（v2 视 issue 再议） |

**决策理由**：本项目将验收范围主动收窄到浏览器，正是为了让"纯 UIA"这条干净路线成立。放弃 B 换来的收益是：无剪贴板污染、无模拟按键被拦截、无密码泄露风险；代价是浏览器以外的应用不保证可用，这一点通过 4.3 的范围声明显式告知。

#### 5.1.1 技术事实核实（2026-10 查证，2026-11-02 实测补充）

| 结论 | 依据 | 对方案的影响 |
|---|---|---|
| **Chrome 138+ 已在 Windows 上默认启用原生 UIA provider**（2025-08-14 官方公告） | Chrome for Developers：《Native UI Automation for Windows in Chromium》 | 过去"必须让用户加 `--force-renderer-accessibility` 启动参数"的历史包袱基本消除，这是纯 UIA 路线成立的关键利好 |
| 原生 UIA 移除了 MSAA→UIA 的模拟代理层，延迟与可靠性显著改善 | 同上 | 取词耗时预期在 10ms 量级，满足 FR-04 的 120ms 气泡要求 |
| 企业环境可用 `UiAutomationProviderEnabled` 策略回退旧模式，该策略支持到 Chrome 146 | 同上 | 存在少数环境被 IT 策略关闭的可能，诊断页需要能识别并提示 |
| `ExpandToEnclosingUnit` 的语义是**规范化（normalize）而非扩展** | Microsoft Learn：`ITextRangeProvider::ExpandToEnclosingUnit` | 见 5.1.2，语境界设计必须据此重写 |
| 该 API 无 "段落" 单位时**会降级到更大的单位**：Character→Format→Word→Line→Paragraph→Page→Document | 同上 | 请求 Paragraph 若不被支持，可能返回 Page 甚至 Document（整页/全文），**存在把整页文本送给模型的风险** |
| `RangeFromPoint` + `ExpandToEnclosingUnit(Word)` 是取"鼠标下单词"的标准用法 | Microsoft DevBlogs《Reading the word under the cursor via UI Automation》 | 为纯 UIA 提供第二条兜底路径（见 5.1.2 方案 A） |

> 以上为公开文档与官方博客的核实结论，**具体到"Chrome 里 `GetSelection()` 能否稳定拿到选中文本"仍需 PoC 实测**（D-1），文档只证明 API 存在，不证明端到端可用。
>
> **2026-11-02 实测补充**：Chrome/Edge 156 下 `ExpandToEnclosingUnit(Paragraph)` 返回选区起点所在段落，单段选区 53–608 字符，**未出现 Paragraph → Page/Document 降级**；`Page` 单位在网页内容上等于整个 `Document`（Martin Fowler 页 45,527 字符），因此 Page 不能作为兜底。跨段选区只保留起点段。完整数据见 [research/uia-validation-2026-11.md](research/uia-validation-2026-11.md)。

#### 5.1.2 兜底路径评估（UIA 取不到时怎么办）

用户提出的"用模拟复制兜底"必须逐条评估后果。结论：**不建议做模拟复制，改推两条纯 UIA / 手动路径**。

| 兜底路径 | 机制 | 可行性 | 风险 | 结论 |
|---|---|---|---|---|
| **A. UIA 第二路径：`RangeFromPoint`** | 用鼠标释放坐标取该点文本范围 → `ExpandToEnclosingUnit(Word)` 拿鼠标下的词 | 高（同一套 UIA 能力，不新增技术栈） | 只能拿单词，拿不到长句；用户选半句时只会得到鼠标下的词；不符合"我选了这一段"的意图 | **推荐纳入 v1.1**，仅用于单词模式兜底 |
| **B. 用户手动复制 + 剪贴板监听** | 用户自己按 Ctrl+C，应用监听剪贴板变化 | 中（实现简单） | 会捕获用户**所有**复制内容（含密码、验证码）；无法判断来源；改变产品交互模型 | 可选，默认关闭，需严格过滤 |
| **C. 模拟 Ctrl+C 自动兜底** | 应用自己注入 Ctrl+C → 读剪贴板 → 还原 | 中 | **见下方致命问题清单** | **不做** |
| **D. 侧边栏输入框手输** | 用户把文本手动粘贴进侧边栏翻译 | 高（最简单） | 需切窗口，违背初衷 | 纳入 v1.1，作为最后出口 |

**模拟复制（方案 C）的致命问题（这也是 4.2 N-2 决策的依据）**

| 级别 | 问题 | 说明 |
|---|---|---|
| **致命** | 密码泄露 | 模拟复制路径只能读到剪贴板文本，**无法判断来源是否为密码框**。密码管理器桌面版、浏览器"显示密码"后选中，均可被复制并发送给第三方模型。UIA 路径有 `UIA_IsPasswordPropertyId` 可拦截，模拟复制路径**没有任何拦截点** |
| **致命** | 终端里 Ctrl+C 是中断信号 | 在 Windows Terminal / PowerShell / cmd 中，Ctrl+C 会终止用户正在运行的命令。这不是"取词失败"，是**破坏用户正在做的事**；而终端恰是读报错信息的常见场景 |
| **高** | 杀软/EDR 误报 | "注入按键 + 读取剪贴板"是键盘记录器的行为特征，Windows Defender 与企业 EDR 拦截概率显著上升，开源工具一旦被标红，信任归零 |
| 高 | 剪贴板污染 | 需"备份→复制→读取→还原"，还原动作会被 Win+V 历史与第三方剪贴板管理器各记一次；若用户在此期间自行复制，内容会丢失 |
| 中 | 时序脆弱 | 不同应用响应 50~500ms 不等，需轮询加超时；慢应用被误判失败，快应用易与用户自己的复制撞车 |
| 中 | 格式不确定 | Excel、网页表格复制出的是 HTML/RTF/CSV，`CF_UNICODETEXT` 可能为空或为拼接结果 |
| 中 | 性能退化一个量级 | UIA 是内存读取（~10ms），模拟复制是"注入按键 + 等 UI 线程 + 轮询剪贴板"（100~500ms），直接击穿 FR-04 的 120ms 气泡指标 |
| 中 | 体验不一致 | 同一操作有时 10ms 有时 300ms，用户感知为"时快时卡" |
| 中 | 降级判定不可写 | "取到空"既可能是 UIA 失败，也可能是用户确实没选中，无法可靠区分，导致每次都要跑两遍 |

**决策**：不实现方案 C。UR-01（UIA 不可用）时，按 A → D 的顺序兜底；仍不满足则引导用户使用浏览器扩展，并在诊断页给出明确说明。

### 5.2 UIA 接入方式（技术关键路径）

| 方案 | 说明 | 风险 | 结论 |
|---|---|---|---|
| A. Node 原生模块（node-ffi / node-addon）调 UIA COM | 与 Electron 同进程 | COM 调用崩溃会带走整个应用；Electron 版本升级需重编译；ffi 在新 Node 上长期有兼容问题 | 不采纳 |
| B. 独立宿主进程（C# .NET 或 Rust）+ IPC | 宿主进程负责钩子与 UIA，崩溃可自恢复 | 多一个进程要打包与守护 | **采纳** |
| C. 纯 C# 写整个应用（WPF） | 无 Electron | 放弃前端技术栈与生态 | 不采纳（用户已定 Electron） |

**推荐 B 的理由**：UIA 是 COM 接口，在 Node 原生模块里调用一旦异常会导致整个渲染进程崩溃，而取词是本产品最高频操作，崩溃不可接受。独立宿主进程可用 named pipe / stdio 与 Electron 主进程通信，崩溃后由主进程重启，且可单独用现成工具调试 UIA 行为。

**宿主进程职责边界**：

1. 安装全局鼠标钩子（WH_MOUSE_LL），在鼠标抬起时读取当前前台窗口进程名，判断是否在白名单。
2. 命中白名单后，用 `AutomationElement.FocusedElement` 或 `ElementFromPoint` 定位元素，取 `TextPattern.GetSelection()`。
3. 若选中文本非空，读取 `UIA_IsPasswordPropertyId` 确认非密码框，上报「取词命中」事件（含文本、选区屏幕坐标、进程名）。
4. 订阅 `UIA_Text_TextSelectionChangedEventId`，作为鼠标钩子之外的补充事件源。
5. **不做任何翻译请求**，不接触 API Key，只做取词与坐标上报。

### 5.3 窗口呈现方案

| 方案 | 不夺焦实现 | 风险 | 结论 |
|---|---|---|---|
| A. `showInactive()` + `alwaysOnTop` + `skipTaskbar` | Electron 原生支持 | 全屏应用下置顶层级可能失效 | **采纳** |
| B. 挤压前台窗口让位（SetWindowPos 改其他进程窗口） | — | 操纵他人窗口，多显示器/最小化/全屏场景易碎 | 不采纳 |
| C. 独立可拖拽窗口 | 需手动激活 | 与"划词即看"距离远 | 不采纳 |

**关键实现约束**：侧边栏使用 `win.showInactive()` 显示，可获得键盘焦点仅在用户主动点击时。因此**所有键盘快捷键在侧边栏未获焦时不可用**，关闭侧边栏必须提供鼠标可点的按钮。

### 5.4 单词结果方案

| 方案 | 音标准确性 | 义项质量 | 成本 | 结论 |
|---|---|---|---|---|
| A. 全部交给 LLM（要求 JSON 输出） | 中（可能出错） | 高（可结合语境） | 0 额外 | **采纳** |
| B. 内置开源词典 + LLM 补语境 | 高 | 高 | 安装包增大 + 词典授权 | 不采纳 |
| C. 在线词典 API | 高 | 中 | 接口不稳定 | 不采纳 |

**决策理由**：唯一刚性需求是"该词在这句话里的意思"，这正是 LLM 的强项；音标准确性通过提示词约束 + 用户反馈（错误可报告）缓解，不为此引入词典库体积。

**已知代价**：音标存在事实性错误风险，PRD 将其列为风险 RK-11 并设计缓解（音标标注来源为模型生成，字号弱化；提供"复制音标反馈"入口）。

### 5.5 长文本方案

| 方案 | 成本控制 | 实现复杂度 | 结论 |
|---|---|---|---|
| A. 超限提示 + 手动确认 | 好 | 低 | 不采纳（用户选 B） |
| B. 自动分段翻译 | 一般（需并发与顺序控制） | 中高 | **采纳** |
| C. 不设上限 | 差 | 低 | 不采纳 |

**采纳 B 的附加约束**（必须同时满足，否则退回 A）：

1. 分段前弹出消耗预估，用户确认后才发请求（防惊喜计费）。
2. 段数与总长度有硬上限。
3. 分段结果必须按原顺序渲染，不能因并发乱序。
4. 单段失败不影响其他段，失败段可单独重试。

## 七、功能需求

> 编号规则：FR-模块序号。状态词统一使用：**必须**（shall）、**应该**（should）、**可以**（may）、**禁止**（must not）。

### 7.1 取词与触发（FR-01 ~ FR-10）

**FR-01 白名单进程判定**
应用**必须**仅在白名单进程的前台窗口中响应选中行为。默认白名单为 `chrome.exe`、`msedge.exe`。
- 用户**可以**在设置中添加/删除进程（通过选择正在运行的进程或手动输入进程名）。
- 添加不在白名单的进程后，**必须**提示"该应用未经完整验证，取词可能失败"。

验收：
- Given 白名单含 `chrome.exe`，When 在 Chrome 中选中英文，Then 触发取词
- Given 白名单不含 `notepad.exe`，When 在记事本中选中英文，Then 不弹气泡、不产生任何请求
- Given 用户添加 `Code.exe`，When 保存，Then 出现"未验证"提示但允许保存

**FR-02 UIA 取词**
宿主进程**必须**通过 UIA `TextPattern.GetSelection()` 获取选中文本。
- 取不到选中文本时，**必须**静默不弹气泡（不提示、不请求）。
- 取到的文本**必须**先做 trim，trim 后为空视为未取到。
- 若目标元素 `UIA_IsPasswordPropertyId` 为真，**必须**跳过，且不记录任何内容。

验收：
- Given Chrome 中选中一段英文，When 鼠标抬起，Then 宿主进程上报取词事件（含文本与选区坐标）
- Given 选中内容在密码输入框中，When 鼠标抬起，Then 不上报、不弹气泡
- Given 目标区域为 canvas 渲染文本（如在线文档），When 选中，Then 无反应（符合范围声明，不计缺陷）

**FR-03 取词事件源**
宿主进程**应该**同时使用两条事件源：全局鼠标钩子（鼠标抬起时主动查询一次）与 `UIA_Text_TextSelectionChangedEventId`（选择变化事件）。
- **禁止**采用定时轮询方式取词（避免 CPU 占用与性能问题）。

验收：
- Given 应用空闲 10 分钟，When 观察进程 CPU，Then 宿主进程平均 CPU 占用 < 0.5%

**FR-04 气泡出现**
取词命中后，**必须**在 120ms 内于选区附近显示气泡。
- 默认位置：选区右下角，水平偏移 8px、垂直偏移 8px。
- 气泡超出屏幕可视区域时，**必须**自动翻转至选区左上角。
- 气泡尺寸**必须** ≤ 96 × 32 px，**禁止**遮挡选中的文本。

验收：
- Given 选中靠近屏幕右下角的文本，When 气泡出现，Then 气泡完整可见且不超出屏幕
- Given 选区在屏幕顶部，When 气泡出现，Then 气泡显示在选区下方或翻转至左侧

**FR-05 气泡消失**
气泡**必须**在以下任一条件满足时消失：点击气泡外的任意位置、选区被清除、鼠标离开气泡 800ms、按下 ESC（应用已获焦时）、用户开始滚动页面。

**FR-06 全局热键触发**
应用**必须**支持全局热键直接翻译当前选中文本，默认 `Alt+D`，用户**可以**修改。
- 热键触发时，若 UIA 取不到选中文本，**必须**给出可见反馈（托盘气泡提示"未获取到选中文本：当前应用可能不支持"），而非静默失败。
- 该反馈是 FR-02"静默不弹气泡"的唯一例外：气泡静默，但用户主动按键时必须给结果。

验收：
- Given Chrome 中已选中英文但气泡已消失，When 按 Alt+D，Then 侧边栏显示该文本译文
- Given 未选中任何文本，When 按 Alt+D，Then 出现托盘提示，且不发送任何请求

**FR-07 热键冲突处理**
设置页**必须**在用户设置热键时检测是否与其他应用冲突，冲突时提示"该组合可能被其他程序占用"。
- 热键注册失败时，**必须**明确告知用户，不得静默失效。

**FR-08 白名单外应用的行为**
非白名单进程中选中文本，应用**禁止**有任何可见或不可见动作（不弹气泡、不请求、不写日志正文）。

**FR-09 全屏应用抑制**
检测到前台应用处于全屏状态时，**应该**暂停气泡显示（避免在视频、演示、游戏中弹窗），热键触发仍可用。

**FR-10 多显示器与 DPI**
气泡与侧边栏位置**必须**按选区所在显示器的 DPI 缩放正确换算，混合 DPI 多屏环境下位置偏差 **必须** ≤ 4px。

### 7.2 文本判定与预处理（FR-11 ~ FR-16）

**FR-11 单词 / 句子模式判定**
- 判定规则：trim 后不含空白字符、长度 ≤ 30、匹配 `^[A-Za-z][A-Za-z'’-]*$` → 单词模式；否则 → 句子模式。
- 选中内容中英文字母占比 < 30% 时，**必须**提示"当前仅支持英文翻译"，不发送请求。

**FR-12 语境界获取（单词模式）**

实现前提（已核实的 API 语义陷阱）：`ExpandToEnclosingUnit` 是**规范化**操作，它先把范围折叠到 Start 端点，再向该端点所在单位对齐。因此：
- 选区**跨段落**时会只保留起始段落 —— 本需求只对单词使用，不受影响，但**禁止**把它用于长选区。
- 请求的单位若不被 provider 支持，**会降级到更大的单位**（Paragraph → Page → Document），**可能返回整页文本**。2026-11-02 在 Chrome/Edge 156 实测未触发该降级；但 `Page` 单位本身等于整个 `Document`，**禁止**用 Page 作为兜底。
- **禁止**用 `Format` 或 `Page` 作为 Paragraph 的兜底：实测 `Format` 可能跨段（655 > 段落 608），也可能只覆盖局部（29 < 段落 191）；`Page` 等于整个 `Document`。
- **实测补充（2026-11-02）**：Paragraph 返回文本可能带尾部换行，Word 单位可能带尾随空格；第 3 步切句前**必须** `trim()`。

因此语境界**必须**用两步法获取，**禁止**直接把 `ExpandToEnclosingUnit(Paragraph)` 的结果当语境界：

```
第 1 步：GetSelection() 拿到选中的词
第 2 步：ExpandToEnclosingUnit(Paragraph) → GetText(2000)  // 读取上限 2000 字符
第 3 步：本地按 . ! ? 切句
第 4 步：定位包含该词的句子 → 取该句 ± 前后各 1 句
第 5 步：若结果 > 300 字符，按词边界截断至 ≤ 300
```

必须满足的约束：
- 第 2 步读取**必须**设长度上限 2000 字符，**禁止**使用 `GetText(-1)`（无限长度），防止拿到整页。
- 第 4 步找不到包含该词的句子（词被拆断、大小写/变形不匹配）时，**必须**回退为"段落首句 + 该词"，仍失败则语境界为空。
- 语境界为空时，**必须**降级为"无语境"模式并在结果首条义项标注"未结合语境"。
- 语境界内容**必须**仅用于本次请求，**禁止**写入日志；个性化配置关闭时也**禁止**写入生词本（见 FR-38）。

验收：
- Given 在普通网页中选中单词 `thread`，When 触发翻译，Then 请求体中的语境界为包含 thread 的句子，且总长 ≤300 字符
- Given 所在段落共 1200 字且含 8 个句子，When 选中其中第 4 句里的一个词，Then 语境界为第 3~5 句，而不是整段
- Given provider 不支持 Paragraph 单位并降级返回整页，When 处理，Then 第 2 步的 2000 字符上限生效，不会把整页送给模型
- Given Chrome/Edge 156 中选中段落内的单词，When 调用 `ExpandToEnclosingUnit(Paragraph)`，Then 返回该段落而非整页（实测 53–608 字符，整页 3,142–45,527 字符）
- Given 语境界扩展失败，When 触发翻译，Then 结果正常返回且首条义项标注"未结合语境"

**FR-13 占位符保护**
送模型前，**必须**识别并替换以下内容为占位符（形如 `\uE000n\uE001`，使用 Unicode 私有区字符避免模型改写）：
- 反引号包裹的行内代码
- URL（`https?://` 起始）
- 文件路径（含 `/` 或 `\` 且带扩展名）
- 命令行参数（`--flag`、`-f`）
- 驼峰 / 下划线 / 短横线标识符（如 `useEffect`、`user_name`、`my-component`）
- 版本号（`v1.2.3`、`^1.0.0`）

替换后**必须**校验：返回结果中的占位符数量与原始一致，不一致则**必须**回退为未保护版本重试一次，仍失败则展示译文并提示"代码保护还原失败"。

验收：
- Given 选中 `Use the useEffect hook to fetch data.`，When 翻译，Then 译文中 `useEffect` 保持英文原样
- Given 选中含 3 个占位符的文本，When 模型返回只含 2 个占位符，Then 触发一次重试并告警

**FR-14 术语表应用**
用户**可以**维护术语表，每条包含：词条、匹配方式（完全匹配 / 包含匹配 / 正则）、处理方式（不译 / 固定译法）、译文（固定译法时必填）。
- 术语表条目**必须**以占位符机制或提示词约束双重方式生效。
- 术语表**应该**支持导入/导出 JSON。

验收：
- Given 术语表含 `thread → 不译`，When 翻译含 thread 的句子，Then 译文中 thread 保留英文
- Given 术语表含 `hook → 固定译法「钩子」`，When 翻译，Then 译文中出现"钩子"而非其他译法

**FR-15 长文本分段**
总长度超过 3000 字符时，**必须**进入分段流程：
- 切分顺序：先按空行分段 → 单段超过 1500 字符则按句末标点切分 → 仍超长则按字符数硬切。
- 硬上限：总字符 ≤ 20000，段数 ≤ 15。超出时**必须**提示并拒绝，不再发送请求。
- 分段结果**必须**按原顺序渲染。
- 并发数**必须** ≤ 3。
- 单段失败**必须**重试 1 次；仍失败则仅该段显示"重试"按钮，其他段正常展示。

验收：
- Given 选中 6000 字符文本，When 触发翻译，Then 提示分段数量与预估消耗，用户确认后按 3 并发请求
- Given 15 段中第 4 段两次失败，When 渲染完成，Then 第 4 段显示重试按钮，其余段正常显示译文

**FR-16 消耗预估**
分段翻译前，**必须**展示"将分 N 次请求，预估输入约 X tokens"（按字符数 ÷ 4 估算，标注"估算"），提供"继续 / 取消"。

### 7.3 翻译引擎（FR-17 ~ FR-23）

**FR-17 引擎配置**
应用**必须**仅支持 OpenAI 兼容接口，配置项：Base URL、API Key、模型名、超时时间（默认 30s）、温度（默认 0.3）、可选云 TTS Key。
- Base URL 默认值**必须**为空，并在占位提示中给出示例格式 `https://api.example.com/v1`。
- **禁止**内置任何 API Key 或默认可用接口。

**FR-18 Key 安全存储**
API Key **必须**使用 Electron `safeStorage` 加密后持久化（Windows 下为 DPAPI，绑定当前用户）。
- **禁止**将 Key 写入日志、崩溃报告、导出的配置文件。
- 设置页**必须**提供"清除 Key"操作。
- 生词本导出文件**禁止**包含 Key。

**FR-19 连通性测试**
配置页**必须**提供"测试连接"按钮，发起一次最小请求（如 1 token 的补全）并返回三种结果之一：成功、认证失败（401/403）、网络不可达。
- 测试**禁止**使用用户的真实待翻译文本。

**FR-20 请求构造**
- 系统提示词**必须**区分单词模式（要求输出 JSON）与句子模式（要求输出译文）。
- 单词模式**必须**要求返回固定结构：

```json
{
  "word": "string",
  "phonetic_us": "string",
  "phonetic_uk": "string|null",
  "context_sense": "string|null",
  "senses": [{ "pos": "string", "def": "string", "example": "string|null" }]
}
```

- 句子模式**必须**返回纯译文文本，**应该**采用流式输出。
- 请求**禁止**携带任何用户标识、设备指纹或元数据。

**FR-21 JSON 解析与降级**
单词模式返回值**必须**做结构校验：
- 解析失败 → 追加"只输出 JSON"约束重试 1 次。
- 仍失败 → **必须**降级为纯文本展示，并提示"结果格式异常，已按文本展示"。

**FR-22 超时与重试**
- 单次请求超时 30s（可配），超时**必须**中止并提示，**禁止**静默等待。
- 流式输出中断时**必须**保留已输出内容并显示"已中断，点击重试"。
- 重试**必须**由用户手动触发（**禁止**自动无限重试，避免消耗用户额度）。

**FR-23 计费可见性**
测试连接之外的每次请求**应该**在当前会话内累计 token 消耗（若接口返回 usage），并在侧边栏底部展示本次会话的估算消耗。

### 7.4 结果呈现（FR-24 ~ FR-32）

**FR-24 侧边栏出现**
点击气泡或热键触发后，侧边栏**必须**在 200ms 内出现（含骨架屏）。
- **必须**使用 `showInactive()` 显示，出现时**禁止**夺取键盘焦点。
- 侧边栏**禁止**出现在任务栏（`skipTaskbar`），**必须**始终置顶（`alwaysOnTop`）。
- 已存在时，**必须**更新内容而非新开窗口；**禁止**同时存在多个侧边栏实例。

**FR-25 侧边栏位置与尺寸**
- 默认停靠屏幕右侧，距右边缘 16px，垂直居中，高度为屏幕可用高度的 60%。
- 宽度**必须**按内容自适应，但受硬约束：最小 320px，最大为屏幕宽度的 40%。
- **必须**提供防跳动规则：同一内容类型（单词 / 句子）在单次会话内宽度变化 **必须** ≤ 60px；跨类型切换时允许重新计算。
- 用户拖拽调整宽度后，**必须**记住该宽度并在后续优先使用；提供"恢复自适应"按钮。

验收：
- Given 先翻译单词（自适应为 320px）再翻译长句，When 内容更新，Then 宽度变化不超过屏幕宽 40% 且过渡平滑无闪烁
- Given 用户拖拽至 600px，When 下次启动应用，Then 侧边栏仍为 600px

**FR-26 单词结果布局**
自上而下**必须**依次呈现：
1. 单词 + 美式音标（必出）+ 英式音标（有则出，字号弱化）
2. 朗读按钮（美式 / 英式）
3. **语境义（置顶）** — 若获取到语境界，展示"在本句中的含义"，并附原句片段
4. 全部义项列表（最多 5 条，每条含词性、释义、可选例句）
5. 底部操作：收藏、复制、反馈

**FR-27 句子结果布局**
- 上方：原文（默认折叠为 3 行，超长可展开）
- 下方：译文，流式逐句渲染
- 分段模式：按原段落顺序排列，每段上方可折叠显示对应原文
- 底部操作：复制译文、朗读译文、收藏

**FR-28 状态展示**
侧边栏**必须**覆盖以下状态，**禁止**出现白屏或无反馈的等待：

| 状态 | 展示要求 |
|---|---|
| 未配置 Key | 空态插画 + 说明 + "去配置"按钮（可跳转设置页并高亮 Key 输入框） |
| 加载中 | 骨架屏（单词模式 3 行骨架，句子模式按段落数生成骨架） |
| 流式中 | 逐字渲染 + 顶部细进度条 |
| 成功 | 正常内容 |
| 请求失败 | 错误码 + 人话说明 + 重试按钮 + "去诊断"入口 |
| 超限 | 明确说明超限原因（字符数 / 段数）与当前值 |
| 不支持语言 | 提示"当前仅支持英文翻译" |
| 未获取语境 | 语境义区域显示"未结合语境"灰字 |

**FR-29 框架无关性**
侧边栏 UI **禁止**依赖所选应用的可访问性能力，任何呈现逻辑不得因取词来源不同而失效。

**FR-30 关闭侧边栏**
- 鼠标点击关闭按钮**必须**可用（不依赖键盘焦点）。
- 应用获焦时，ESC **应该**可关闭。
- 设置中提供"失去焦点后自动隐藏"选项，**默认关闭**（避免用户阅读原文时误关）。

**FR-31 复制功能**
复制译文**必须**写入系统剪贴板，且**必须**在 1.5s 内给出"已复制"反馈。
- 若剪贴板中存在其他内容，**禁止**在未提示的情况下覆盖超过 1 次（防污染争议）。

**FR-32 主题**
侧边栏**必须**支持浅色 / 深色 / 跟随系统三种主题，**默认跟随系统**。

### 7.5 生词本与会话历史（FR-33 ~ FR-38）

**FR-33 收藏**
- 侧边栏**必须**提供收藏按钮，收藏内容为：词条、音标、语境义、义项列表、例句、来源 URL（若可取）、创建时间、标签（可选）。
- 重复收藏同一词条时，**必须**提示"已存在"，并提供"更新"或"取消"。

**FR-34 会话历史**
- 应用**必须**在内存中保留本次运行最近 20 条翻译记录。
- **必须**提供入口查看（侧边栏底部"最近"）。
- 点击历史条目**必须**恢复该条结果（不重新请求）。
- 应用退出后历史**必须**清空，**禁止**落盘。

**FR-35 生词本存储**
- 生词本**必须**持久化到本地 SQLite（`%APPDATA%/<app>/vocab.db`）。
- **禁止**存储任何未主动收藏的内容。

**FR-36 生词本管理**
**必须**支持：列表（按时间倒序）、关键词搜索（匹配词条与释义）、单条删除、批量删除、清空全部（二次确认）。

**FR-37 导出**
**必须**支持导出为 CSV 与 JSON，导出**必须**使用系统保存对话框由用户指定路径。
- CSV **必须**为 UTF-8 with BOM（保证 Excel 打开不乱码）。

**FR-38 隐私边界**
- 生词本**禁止**包含完整原文段落（仅保留语境界片段 ≤ 300 字符，且可设置关闭）。
- 设置页**必须**提供"我收藏了什么"的完整查看入口与一键清空。

### 7.6 朗读（FR-39 ~ FR-42）

**FR-39 系统 TTS**
- 默认使用 Windows 系统语音（`speechSynthesis`）。
- 单词模式朗读单词，句子模式朗读译文。
- 语速**应该**可调（0.5x ~ 1.5x）。

**FR-40 云 TTS**
- 用户**可以**在设置中填入云 TTS 服务配置（OpenAI 兼容 `/v1/audio/speech` 或 Azure），填了则优先使用，未填则回落系统 TTS。
- 云 TTS 失败时**必须**自动回落系统 TTS 并提示"云朗读失败，已使用系统语音"。

**FR-41 朗读可用性**
- 系统无可用语音包时，朗读按钮**必须**置灰并提示"系统未安装语音"。
- 朗读**禁止**阻塞其他操作。

**FR-42 音频文件**
云 TTS 返回的音频**必须**仅存于内存或临时目录，**必须**在应用退出时清理。

### 7.7 配置与首启（FR-43 ~ FR-49）

**FR-43 首次启动引导**
首次启动**必须**展示 3 步引导（**可以**跳过）：
1. 一句话说明 + 数据流向声明（选中内容会发至你配置的接口，本应用无服务器）
2. 配置 API（Base URL / Key / 模型名）+ 测试连接
3. 权限与自检（UIA 是否可用、白名单是否生效），提供"立即试一次"跳转到 Chrome

- 跳过配置**必须**允许进入主界面，未配置时侧边栏显示"未配置"空态。

**FR-44 配置项清单**

| 分组 | 配置项 | 默认值 |
|---|---|---|
| API | Base URL / Key / 模型名 / 超时 / 温度 | 空 / 空 / 空 / 30s / 0.3 |
| 取词 | 白名单进程 / 全局热键 / 气泡位置偏好 / 全屏抑制 | chrome.exe, msedge.exe / Alt+D / 右下 / 开 |
| 呈现 | 主题 / 侧边栏宽度 / 失焦自动隐藏 / 字号 | 跟随系统 / 自适应 / 关 / 14 |
| 术语 | 术语表 / 导入导出 | 空 |
| 数据 | 生词本路径 / 语境界片段是否入库 / 一键清空 | 默认路径 / 开 |
| 系统 | 开机自启 / 托盘提示 / 界面语言 | 关 / 开 / 跟随系统 |
| 朗读 | 语音引擎 / 云 TTS 配置 / 语速 | 系统 / 空 / 1.0 |

**FR-45 配置持久化**
配置**必须**存于 `%APPDATA%/<app>/config.json`，Key 字段**必须**为密文。
- 配置文件损坏时，**必须**备份原文件并以默认配置启动，同时提示。

**FR-46 自检诊断**
设置页**必须**提供"诊断"功能，输出以下检查结果（可复制为文本）：

| 检查项 | 输出内容 |
|---|---|
| 版本 | 应用版本、宿主进程版本、Electron 版本 |
| UIA 可用性 | 能否枚举当前前台窗口的 TextPattern |
| 白名单 | 当前生效的进程列表 |
| 热键 | 是否注册成功 |
| API | Base URL 可达性、认证结果（不显示 Key） |
| 代理 | 是否检测到系统代理 |
| TTS | 系统语音数量、云 TTS 配置状态 |
| 日志 | 最近 50 条错误（脱敏） |

**FR-47 开机自启**
设置项默认关闭，开启时**必须**通过注册表 `HKCU\...\Run` 实现（**禁止**写 HKLM），关闭时**必须**完整移除。

**FR-48 单实例**
应用**必须**单实例运行，第二次启动时**必须**唤起已有实例（显示侧边栏或设置页），**禁止**出现两个托盘图标或两次热键注册。

**FR-49 中英双语界面**
界面文案**必须**抽离为 i18n 资源文件，**必须**支持中文与 English 切换，默认跟随系统语言，无法识别时默认中文。

### 7.8 系统集成（FR-50 ~ FR-53）

**FR-50 托盘**
- 关闭主窗口**必须**最小化到托盘而非退出（首次关闭时提示一次）。
- 托盘菜单**必须**包含：显示/隐藏侧边栏、设置、诊断、退出。

**FR-51 退出**
退出时**必须**：注销热键、卸载鼠标钩子、终止宿主进程、清理临时音频、关闭数据库连接。

**FR-52 崩溃恢复**
宿主进程异常退出后，主进程**必须**在 3s 内自动重启并恢复取词能力；连续 3 次失败则**必须**提示用户并停止重试。

**FR-53 更新提示**
应用**应该**在启动时检查 GitHub Releases 最新版本号（仅比较版本号，不下载），有新版时在设置页显示"有新版本"链接。
- 本期**禁止**实现自动下载与静默安装。

### 7.9 AI 能力专项（六模块契约）

| 模块 | 本产品定义 |
|---|---|
| **1. 任务定义** | 用户在浏览器阅读英文时，基于选中的片段（及可选的所在段落），需要得到"能立刻理解"的中文结果。AI 帮到「直接给出可用结果」这一步，不做二次确认。主要成本是阅读中断，不是翻译本身 |
| **2. 输入契约** | 输入＝选中文本（必填，trim 后非空）+ 语境界（单词模式可选，≤300 字符）。缺失语境界时降级不追问。冲突规则：若语境界与选中文本矛盾（选区不在扩展段内），以选中文本为准并丢弃语境界。超长输入按 FR-15 分段，不做摘要 |
| **3. 输出契约** | 单词模式：固定 JSON（见 FR-20），字段缺失视为不合格。句子模式：纯译文，**禁止**夹杂解释、**禁止**输出原文、**禁止**输出 Markdown 标题。**禁止**输出任何与译文无关的建议或推销语。证据形式：语境义**必须**引用原句片段（≤50 字符）以便用户核对 |
| **4. 质量标准** | 六个维度：事实正确（音标与释义不编造）、信息完整（义项覆盖主要词性）、格式合规（JSON 可解析）、表达合适（中文通顺、技术词不硬译）、来源可靠（语境义有原句支撑）、支持下一步（可直接复制/收藏）。验收样本：50 条自建评测集（含 20 个多义词、10 条含代码的句子、10 条长难句、10 条短句），每条标注「可接受 / 不可接受」条件。阈值：评测集准确率 ≥ 85%，JSON 解析成功率 ≥ 98% |
| **5. 异常降级** | 幻觉（音标/释义可疑）→ 弱化展示并标"AI 生成"；低置信（语境界缺失）→ 标注"未结合语境"；多源冲突（占位符数量不符）→ 回退重试一次；请求失败 → 保留输入、显示重试；超长 → 分段或拒绝。**禁止**统一显示"系统繁忙"。人工接管：本期无人工，失败即由用户手动重试或复制原文外查 |
| **6. 反馈与版本闭环** | 侧边栏**必须**提供"结果有问题"入口，记录：问题类型（音标错 / 释义错 / 代码被译 / 其他）+ 原文 + 结果，默认**仅存本地**（用户可自行导出贴到 issue）。每条结果**必须**在诊断日志中关联：应用版本、模型名（**禁止**记录 Key）、提示词版本号、是否启用术语表、是否启用占位符保护 |

**AI 行为约束三层**：

| 层级 | 约束 |
|---|---|
| Always do | 只翻译选中的文本、保留占位符、单词模式输出固定 JSON、语境义引用原句 |
| Ask first | 长文分段前确认消耗、覆盖剪贴板、批量删除生词本、清空全部数据 |
| Never do | 发送未选中的内容、上传 Key 以外的用户信息、访问除用户配置的 Base URL 以外的任何地址、在密码框中取词、把原文写入日志、自动重试消耗用户额度 |

| 可维护性 | 渲染层与取词层通过明确 IPC 契约解耦 | 代码审查 |
| 可维护性 | 引擎适配层可新增实现而不改业务逻辑 | 代码审查 |

## 九、业务流程与状态流转

### 9.1 主流程（取词 → 呈现）

```
用户拖选文本
   ↓
宿主进程：鼠标抬起 → 取前台进程名
   ↓
[不在白名单] → 结束（无任何动作）
   ↓ 在白名单
UIA TextPattern.GetSelection()
   ↓
[取不到 / 密码框 / 空白] → 结束（静默）
   ↓ 取到
计算选区屏幕坐标 → 渲染气泡（≤120ms）
   ↓
[用户忽略 / 点击别处 / 800ms 无悬停] → 气泡消失，结束
   ↓ 用户点击气泡 或 按 Alt+D
文本预处理（模式判定 / 语言校验 / 占位符替换 / 术语表）
   ↓
[未配置 Key] → 侧边栏空态 + 去配置
   ↓ 已配置
[超长] → 分段流程（预估 → 确认 → 并发 3）
   ↓ 正常
请求 API（句子模式流式 / 单词模式 JSON）
   ↓
渲染结果（单词：语境义置顶 + 义项；句子：原文折叠 + 译文）
   ↓
[用户点收藏] → 写入 SQLite → 提示已收藏
[用户点朗读] → 系统 TTS 或云 TTS
[用户关闭] → 侧边栏隐藏（内存历史保留）
```

### 9.2 侧边栏状态机

| 状态 | 触发事件 | 允许操作 | 迁移目标 |
|---|---|---|---|
| Hidden | 点击气泡 / 热键 | — | Loading 或 Empty |
| Empty | 未配置 Key | 去配置、关闭 | Hidden / Loading |
| Loading | 请求已发出 | 取消、关闭 | Streaming / Done / Error |
| Streaming | 收到首包 | 复制（部分）、关闭 | Done / Error |
| Done | 流结束 / JSON 解析成功 | 收藏、复制、朗读、关闭、重试 | Loading（新请求） |
| Error | 失败 / 超时 / 解析失败 | 重试、诊断、关闭、复制原文 | Loading |
| Limit | 超长 / 语言不符 | 关闭、去设置 | Hidden |

> 状态迁移**必须**单向可控：**禁止**从 Done 回跳 Streaming；新请求**必须**先清空上一条内容（防串台）。

### 9.3 分段翻译状态

| 阶段 | 行为 |
|---|---|
| 切分 | 生成段数组，每段含 `index / text / 状态` |
| 预估 | 计算段数、字符数、token 估算，等待用户确认 |
| 执行 | 并发 ≤3，逐段状态 pending → running → success/failed |
| 渲染 | 按 index 顺序渲染，未完成段显示骨架，失败段显示重试 |
| 收敛 | 全部结束或用户取消；取消时保留已完成段 |

失败处理：单段重试 1 次自动，仍失败转手动；**禁止**整批重发。

## 十、数据与埋点需求

### 10.1 数据实体

| 实体 | 字段 | 存储 | 生命周期 |
|---|---|---|---|
| 配置 Config | 见 FR-44 | `config.json`（Key 密文） | 持久 |
| 生词 Vocabulary | id / word / phonetic_us / phonetic_uk / context_sense / context_snippet / senses(JSON) / source_url / tags / created_at | SQLite | 持久，用户可删 |

| 诊断日志 LogEntry | 时间 / 级别 / 模块 / 错误码 / 文本长度 / 耗时 | `logs/` 文件 | 保留 7 天，滚动删除 |

### 10.2 日志脱敏规则（强制）

| 内容 | 处理 |
|---|---|
| 选中原文 / 译文 | **禁止**记录（仅记录字符数） |
| API Key | **禁止**记录（仅记录"已配置/未配置"） |
| Base URL | 仅记录域名，**禁止**记录完整路径与查询参数 |
| 错误信息 | 记录 HTTP 状态码与错误类型，**禁止**记录响应体全文 |
| 进程名 | **允许**记录（用于排查白名单问题） |

### 10.3 指标定义

| 指标 | 口径 | 用途 |
|---|---|---|
| 取词成功率 | UIA 命中次数 ÷ 鼠标抬起且白名单内次数 | 衡量取词链路健康度（本地） |
| 气泡出现耗时 | 鼠标抬起 → 气泡 `did-finish-load` | 性能回归 |
| 首字延迟 | 点击 → 首字渲染 | 体验观测 |
| 结果成功率 | 成功渲染 ÷ 请求总数（按错误码分布） | 定位接口问题 |
| JSON 解析成功率 | 首次解析成功 ÷ 单词模式请求数 | 检验提示词质量 |
| 占位符还原成功率 | 还原成功 ÷ 含占位符请求数 | 检验保护机制 |

> **全部指标仅本地计算与展示（诊断页），默认不上报任何服务器。** 本项目无服务端，指标用于用户自助排查与开发者收集 issue 时索取。

## 十三、上线计划、依赖与上线后验证

### 13.1 依赖就绪度评估

| 编号 | 依赖项 | 所属 | 分级 | 最晚就绪时限 | 未就绪的影响与替代 |
|---|---|---|---|---|---|
| D-1 | **UIA 在 Chrome/Edge 取选中文本的可行性 PoC** | 技术 | **阻塞** | 开发第 1 周内 | 若 PoC 不成立，按 5.1.2 顺序回退（方案 A `RangeFromPoint` → 方案 D 输入框 → 重新评估技术路线）；**必须**在写业务代码前完成。**不采用模拟复制路线**（见 5.1.2 致命问题） |
| D-2 | 宿主进程打包与 IPC 链路打通 | 技术 | 阻塞 | 开发第 2 周 | 无法取词，需改用 Node 原生模块（风险更高） |
| D-3 | 用户自备 OpenAI 兼容 Key 与可用网络 | 外部 | 并行 | 联调前 | 无 Key 无法联调；可用用户自己的中转服务或本地 Ollama 兼容接口替代 |
| D-4 | Windows 代码签名证书 | 发布 | 可绕过 | 发布前 | 无签名 → SmartScreen 警告；替代方案为 README 显著说明 + 提供 SHA256 校验值 |
| D-5 | 图标与视觉资源 | 设计 | 可绕过 | 发布前 | 用占位图标发布，后续替换 |
| D-6 | 云 TTS 账号（可选功能） | 外部 | 可绕过 | 不做也不影响上线 | 仅系统 TTS 可用 |

> **D-1 是本项目的生死线**。它决定"纯 UIA"这条路线是否成立。PRD 建议在投入任何界面开发之前，用 1~2 天写一个最小 UIA 探针程序，在 3 类页面上验证：普通文章页（如英文维基）、GitHub README、含 iframe 的页面。

**D-1 PoC 验收标准**：在上述 3 类页面各选 10 次（单词 5 次、句子 5 次），取词成功率 ≥ 90%，单次取词耗时 ≤ 50ms，不产生任何剪贴板写入。同时验证三项衍生能力：

| 衍生验证项 | 判定标准 |
|---|---|
| 语境界颗粒度 | `ExpandToEnclosingUnit(Paragraph)` + `GetText(2000)` 返回的文本长度中位数 ≤ 800 字符，且不是整页文本 |
| 选区跨段行为 | 选区跨 2 个段落时，结果只保留起始段（符合规范化语义，用于确认 FR-12 的约束理解正确） |
| `RangeFromPoint` 兜底可用率 | 在无选区状态下，鼠标指向某个英文单词并调用 `RangeFromPoint` + `ExpandToEnclosingUnit(Word)`，能取到该词的比例 ≥ 90% |

> **2026-11-02 进展**：Q-1（Paragraph 颗粒度）已完成；D-1 主项（3 类页面各 10 次、成功率 ≥ 90%、单次 ≤ 50ms、iframe）尚未按验收标准跑完。已完成的单点验证见 [research/uia-validation-2026-11.md](research/uia-validation-2026-11.md)。

未达标准则触发方案回退评审（回退顺序：5.1.2 方案 A → 方案 D → 重新评估整体技术路线）。
