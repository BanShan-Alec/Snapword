# 沉浸式翻译（本地安装版）三窗口交互调研

> 调研日期：2026-11-02
> 调研对象：本机已安装的「沉浸式翻译」浏览器扩展
> Chrome：`bpoadfkcbjbfhfodiogcnhhhpibjhbnh`，版本 `1.34.4`，路径 `%LOCALAPPDATA%\Google\Chrome\User Data\Default\Extensions\...`
> Edge：同 ID，版本 `1.33.1`
> 方法：读取本地安装包的 `manifest.json`、`content_main.js`、`options.js`、`side-panel.js`、`styles/inject.css`、`default_config.content.json`、`locales.json`；未登录账号、未发起真实翻译请求。
>
> 本报告只记录**界面结构与交互行为**，不评估其实现技术，也不作为 Snapword 照搬的依据。Snapword 的取舍见第 4 节。

---

## 1. 结论先行

沉浸式翻译的划词链路是清晰的三层结构：

```
划词 → 小圆点（入口） → 翻译卡片（阅读与操作） → 主界面 / 侧边栏（管理与设置）
```

三层各自只做一件事：

| 层                      | 角色                   | 用户动作                       | 不做什么                             |
| ----------------------- | ---------------------- | ------------------------------ | ------------------------------------ |
| 调研对象圆点            | 「这里可以翻译」的入口 | 点击或悬停                     | 不展示译文、不放多个按钮、不打断阅读 |
| 调研对象卡片            | 当前这一次翻译的阅读面 | 读、复制、朗读、收藏、调大小   | 不承担历史管理、不承担完整设置       |
| 调研对象主界面 / 侧边栏 | 长期管理面             | 配置、查历史、管理术语、看教程 | 不抢划词当下的注意力                 |

上表记录沉浸式翻译的交互，不代表 Snapword 采纳项；Snapword 的当前取舍见第 4 节。

这个分层正好对应 Snapword 这次要改的三窗口模型。Snapword 可以直接沿用「入口 → 阅读 → 管理」的层级，但需要把浏览器扩展的页面内交互改成桌面应用的独立置顶窗口交互。

## 2. 第一层：划词小圆点

### 2.1 触发方式

扩展提供三种划词触发方式（`selectionTranslation.triggerMode`）：

| 模式     | 用户看到什么         | 行为                 |
| -------- | -------------------- | -------------------- |
| `direct` | 不出现入口           | 选中后直接发起翻译   |
| `icon`   | 选区旁出现品牌图标   | 悬停或点击图标后翻译 |
| `mini`   | 选区旁出现一个小圆点 | 悬停或点击圆点后翻译 |

本地默认配置里 `triggerMode` 为 `mini`，同时 `triggerModeForIcon` 为 `hover`。也就是说，沉浸式翻译默认交互为「悬停小圆点」，首次使用引导也写「悬停小圆点翻译」；这是调研对象行为，不代表 Snapword 决策。

Snapword 这次明确采用**点击圆点**：点击比悬停更可控，不会因为鼠标路过就产生请求，也避免误触。悬停触发在本期不做，最多作为后续设置项。

### 2.2 小圆点的视觉与尺寸

从小圆点组件 `LXe` 与样式 `PXe` 提取：

| 项       | 值                                                                                             |
| -------- | ---------------------------------------------------------------------------------------------- |
| 视觉尺寸 | `9 × 9 px`                                                                                     |
| 形状     | 正圆                                                                                           |
| 边框     | `1px solid #FFF`                                                                               |
| 填充     | `#F1548E`                                                                                      |
| 阴影     | `0 1px 3px rgba(38, 16, 27, 0.18)`                                                             |
| 定位     | `position: absolute`，`transform: translate(-50%, -50%)`                                       |
| 层级     | `z-index: 2147483647`                                                                          |
| 光标     | `pointer`                                                                                      |
| 引导气泡 | 沉浸式翻译首次出现时显示「悬停小圆点翻译」，位于圆点下方 14px；Snapword MVP 不采用首次出现引导 |

小圆点没有文字、没有图标、没有第二个按钮，点击热区就是 9px 本身。这个尺寸在浏览器页面里够用，但对桌面应用来说偏小；Snapword 应保留「视觉小、热区大」的原则，而不是照搬 9px 点击热区。

### 2.3 小圆点的出现与消失

从 `fhe`、`xhe`、`w1` 等逻辑看：

- 圆点定位以选区或鼠标释放点为锚点，默认在选区附近，偏移约 8–10px。
- 圆点出现后，点击页面其他位置会移除圆点与卡片（除非卡片被固定）。
- 选区变化、页面滚动、窗口切换时，圆点不会长期停留在错误位置。
- 圆点本身不可拖动，位置由选区决定。
- 没有「鼠标移出 800ms 自动消失」这类倒计时；它更像一个锚点，而不是一个确认按钮。

Snapword 的当前决策：MVP 圆点不设自动隐藏计时器，也不提供自动隐藏设置；自动隐藏、位置偏好、首次出现引导均列入 v1.1 规划。

### 2.4 小圆点的状态

| 状态      | 视觉            | 进入条件      | 退出                   |
| --------- | --------------- | ------------- | ---------------------- |
| Hidden    | 不可见          | 初始 / 已消失 | 取词命中               |
| Appearing | 淡入 + 轻微放大 | 取词命中      | 动画结束               |
| Idle      | 静态圆点        | 动画结束      | 悬停 / 点击 / 消失条件 |
| Hover     | 放大、出现外圈  | 鼠标进入      | 鼠标移出               |
| Pressed   | 缩小            | 鼠标按下      | 松开触发               |
| Fading    | 淡出            | 关闭条件      | 动画结束               |

扩展没有明显的「悬停放大」样式，但这是桌面端小热区常见的可用性补偿。调研对象有悬停视觉反馈；Snapword 当前只采用微弱提示，不明显放大或加明显光晕，且不触发翻译。

## 3. 第二层：翻译卡片

### 3.1 卡片的基本形态

从 `content_main.js` 中提取的卡片根样式与组件：

| 项       | 值                                                        |
| -------- | --------------------------------------------------------- |
| 根类名   | `immersive-translate-modal`（`V` 为品牌前缀）             |
| 默认宽度 | `450px`                                                   |
| 最小宽度 | `280px`（窄屏兜底）                                       |
| 最大宽度 | `calc(100vw - 24px)`，且不超过视口                        |
| 圆角     | `16px`                                                    |
| 内边距   | `16px 20px`，顶部为 0（头部单独留白）                     |
| 阴影     | `0 10px 32px rgba(0, 0, 0, 0.08)`                         |
| 深色背景 | `#222`，阴影改为白色低透明度                              |
| 默认位置 | 选区附近，偏移 `10px`；优先跟随鼠标锚点                   |
| 兜底位置 | 视口底部居中，距底部 `24px`，宽度 `min(450, 视口宽 - 24)` |
| 拖拽     | 整个标题栏可拖动，`cursor: move` / `grabbing`             |
| 缩放     | 仅句子模式显示右下角 `20 × 20` 缩放手柄                   |
| 最大高度 | 卡片自身受视口约束；结果区内部最大高度 `300px`，超出滚动  |
| 关闭按钮 | 头部右侧，`28 × 28` 点击区                                |
| 固定     | 沉浸式翻译头部有 Pin 按钮；固定后不随点击外部关闭         |
| 历史翻页 | 头部左侧显示 `‹ 1/N ›`，同一卡片内可翻看多条结果          |

这套尺寸对 Snapword 的参考价值在于：**卡片不是侧边栏，宽度不需要占满屏幕右侧；它是一个贴着选区的小型阅读面**。450px 是调研对象的尺寸；Snapword 当前决策为固定 420px，只有屏幕可用空间不足时夹限到可用宽度，不使用最小/最大比例规则。

### 3.2 卡片头部

头部从左到右：

1. 品牌图标。
2. 卡片内历史翻页：`‹ 1/3 ›`，仅在有多条结果时出现。
3. 翻译服务下拉框（仅 AI 服务）。
4. 「用文本翻译对比」图标。
5. Pin 固定按钮。
6. 句子显示模式切换（双语 / 仅译文）。
7. 更多菜单。
8. 关闭按钮。

更多菜单包含：

- 自动朗读开关
- 双语 / 仅译文切换
- 禁用划词翻译：本次关闭 / 当前网站禁用 / 永久关闭
- 去设置

Snapword 不需要服务下拉与「文本翻译对比」；当前头部只保留「防误关」、更多、关闭。「在主窗口打开」与设置放在「更多」菜单中；MVP 不提供双语/仅译文切换，卡片始终显示折叠原文与译文，完整原文可展开。

### 3.3 原文区

原文区是一个独立卡片：

| 项          | 值                                                  |
| ----------- | --------------------------------------------------- |
| 背景        | 浅色 `#FAFBFB`，深色 `#1D1E1E`                      |
| 圆角        | `12px`                                              |
| 内边距      | `12px`                                              |
| 字号 / 行高 | `14px / 21px`                                       |
| 折叠        | 默认折叠为 2 行（`-webkit-line-clamp: 2`）          |
| 展开        | 超过 2 行时显示「显示全部」；展开后显示「折叠内容」 |
| 原文操作    | 朗读原文、复制原文                                  |
| 滚动        | 展开后最大高度 300px，内部滚动                      |

Snapword 当前原文区采用 3 行折叠：技术文档句子经常较长，2 行容易截断；3 行仍能控制卡片高度。

### 3.4 结果区

**单词模式**：

- 词头：原词 + 音标 + AI 标注（若音标由模型生成）+ 朗读按钮。
- 释义：按词性分组，最多 5 条。
- 语境义：单独一块，位于释义上方或下方（扩展放在结果区中）；Snapword 继续坚持「语境义置顶」。
- 底部：反馈（赞/踩/问题反馈）。

**句子模式**：

- 译文主字号 `16px`，字重 `700`，行高 `1.5`。
- 长文按段落/块渲染，每块可单独显示原文。
- 流式输出有光标；底部操作栏在流式过程中仍可点（允许复制前半段）。
- 双语 / 仅译文可切换。

### 3.5 卡片操作与状态

| 操作     | 行为                                                           |
| -------- | -------------------------------------------------------------- |
| 复制     | 点击后图标变为成功态，2 秒后恢复；不弹 toast                   |
| 朗读     | 播放 / 停止 toggle；无语音包时置灰                             |
| 收藏     | 星标实心 / 空心；重复收藏显示「更新 / 取消」                   |
| 反馈     | 赞 / 踩 / 问题反馈，内联展开                                   |
| 拖拽     | 标题栏拖动；松手后若超出视口，自动回弹到可视区域               |
| 缩放     | 句子模式右下角手柄；最小尺寸受内容约束                         |
| 固定     | Pin 后不因点击外部关闭；ESC 也不关闭                           |
| 关闭     | 头部关闭按钮；ESC 仅在卡片已获焦且未固定时生效                 |
| 外部点击 | 未固定时关闭卡片；固定时保持                                   |
| 卡片历史 | 新结果进入卡片栈，头部翻页；关闭卡片后清空卡片栈，主历史仍保留 |

### 3.6 卡片的加载与异常

- 打开卡片后先显示骨架屏，不出现白屏。
- 单词模式骨架约 4–6 行；句子模式按段落数生成骨架。
- 加载超过 3 秒显示「接口响应较慢，仍在请求中…」。
- 错误在卡片内显示，不跳系统对话框；错误文案三段式：发生了什么 + 为什么 + 怎么办。
- 长文在卡片内做消耗预估，不用系统模态框；取消即不发请求。
- 分段失败只影响该段，段内显示重试。

### 3.7 主界面：设置页 / 侧边栏

本地扩展的主界面有两套：

1. **Options 页**：完整设置，本地化文案包含「基本设置 / 进阶设置 / 开发者设置 / 问题反馈 / 关于」等入口。
2. **Side Panel**：文本翻译、教程、历史记录等日常入口。

设置页的交互习惯：

- 大多数开关即时生效，没有「保存」按钮。
- 设置项按分组折叠，长说明用问号提示，不把帮助文字堆在界面上。
- 翻译服务、语言、样式等选择项放在同一组，避免来回跳页。
- 危险操作（重置、删除云端配置）需要二次确认。

Snapword 的主窗口借鉴「左侧导航 + 分组设置 + 即时生效」；当前信息架构为翻译、翻译历史、生词本、术语表、设置、帮助与诊断。术语表与帮助/诊断（含关于）是顶层页，不在设置中重复；历史和生词本清空操作分别留在各自页面。

## 4. 对 Snapword 的取舍

### 4.1 直接沿用

| 交互                           | Snapword 当前决策                                                             |
| ------------------------------ | ----------------------------------------------------------------------------- |
| 三层结构：圆点 → 卡片 → 主窗口 | 入口、阅读、管理分离；主窗口页面为翻译/翻译历史/生词本/术语表/设置/帮助与诊断 |
| 圆点贴身、极小、无文字         | 点击触发翻译；悬停只作微弱视觉提示，不自动翻译；MVP 不含首次出现引导          |
| 卡片靠近选区                   | 固定宽度 420px，仅屏幕可用空间不足时夹限；只可拖动位置，不缩放                |
| 卡片防误关                     | 仅阻止点击卡片外部（含主窗口）关闭；不锁内容；切换到其他应用仍关闭            |
| 原文折叠 / 展开                | 长句不撑爆卡片；高度随内容自适应并设上限                                      |
| 复制 / 朗读 / 收藏内联反馈     | 操作成功/失败状态提示保留；这不等于卡片赞/踩/问题反馈                         |
| 加载骨架、流式光标、段内重试   | 状态可见、失败可恢复；流式可停止，停止后需用户点击重试                        |

### 4.2 需要改造

| 扩展行为                | Snapword 的做法                                                                   | 原因                                        |
| ----------------------- | --------------------------------------------------------------------------------- | ------------------------------------------- |
| 悬停圆点触发            | **点击圆点触发**                                                                  | 避免鼠标路过产生请求；点击更可控            |
| 9px 点击热区            | 视觉 10px，热区 ≥24px                                                             | 桌面鼠标精度与可访问性                      |
| 450px 固定宽度          | 固定 420px；仅屏幕可用空间不足时夹限                                              | 不随内容或屏幕比例动态缩放，不提供用户缩放  |
| 卡片内历史翻页          | **不做**；卡片只显示当前结果，历史统一主窗口；翻译页显示共享最近 20 条中的前 5 条 | 避免卡片和主窗口各有一套历史                |
| 双语 / 仅译文切换       | **不做 MVP**；卡片始终显示折叠原文与译文，完整原文可展开                          | 用户确认 MVP 不做显示模式切换；减少卡片决策 |
| 卡片缩放                | **不做 MVP**；只保留拖动位置                                                      | 用户确认固定 420px，不提供缩放              |
| 浏览器页面内注入        | 独立置顶卡片窗口                                                                  | Snapword 是桌面应用，需要跨应用             |
| 服务下拉 / 多服务切换   | 不在卡片内切换，统一在设置中配置                                                  | 单引擎产品，减少卡片头部噪音                |
| 当前网站禁用            | 白名单 / 当前应用暂停                                                             | 桌面应用没有「网站」概念                    |
| Pro 升级、试用、账号    | 不做                                                                              | 与 Snapword 开源、无账号定位冲突            |
| 页面翻译、PDF、视频字幕 | 不做                                                                              | 超出划词翻译范围                            |

### 4.3 明确不学

| 扩展行为                   | 不学的原因                                             |
| -------------------------- | ------------------------------------------------------ |
| 悬停即翻译                 | 用户没有显式确认，容易产生意外请求与费用               |
| 卡片内多服务下拉           | 增加决策负担，且 Snapword 只支持用户自配的一个兼容接口 |
| 付费墙 / 试用引导          | 与开源、无服务器定位冲突                               |
| 把「禁用划词」藏进卡片菜单 | Snapword 的开关应放在主窗口设置里，卡片只做当前结果    |
| 首次使用强制引导           | 引导可跳过，不阻断主流程                               |

## 6. 对 Snapword 的直接启示

1. **圆点是显式翻译入口。** 点击触发；悬停只作微弱视觉提示，不发起请求。
2. **卡片只呈现当前结果。** 固定宽度 420px（仅屏幕空间不足时夹限），仅可拖动位置；防误关只拦截外部点击关闭，应用切换仍关闭。
3. **主窗口是管理与手动翻译入口。** 页面固定为翻译、翻译历史、生词本、术语表、设置、帮助与诊断；翻译页呈现共享历史前 5 条。
4. **只有一份共享会话历史。** 两个翻译入口共用最近 20 条；历史查看卡片不请求、不新增历史，后台主窗口请求继续且不得覆盖卡片当前展示。
5. **操作状态提示不等于反馈入口。** 复制、收藏、朗读的成功/失败提示保留；卡片赞/踩/问题反馈不进 MVP、列入 v1.1，帮助页 GitHub issue 入口保留。
6. **成本展示分两类。** 本次运行用量 累计显示不进 MVP、列入 v1.1；长文分段发送前消耗预估保留。
7. **托盘重开复用缓存。** 使用最近一条已完成历史，不发请求、不新增历史、不抢焦；无历史时置灰。
